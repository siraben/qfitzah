# Plan: Bootstrapping GNU Mes on the qfitzah ladder (no C layer)

**Thesis.** Replace the C leg of the Mes bootstrap (hex0…M2-Planet compiling
`src/*.c`) with the qfitzah ladder (assembly seed → term rewriting → Scheme
compiler), producing a Mes-core-compatible interpreter with no C compiler
anywhere below it, then run Mes's own Scheme boot chain and MesCC on top and
show the MesCC output artifacts are byte-identical to the M2-Planet path.

## Executive verdict

The thesis is achievable, by one path only: **write the Mes interpreter core as
a faithful transliteration of `src/*.c` into the rsc dialect ("qmes"), compile
it natively with the existing Stage 4 rsc compiler, and run Mes's unmodified
boot files and MesCC on it** (Strategy A below). Every hard property Mes needs —
explicit-stack VM, define-macro, call/cc, copying GC, hash tables, structs,
string ports — is *internal* to the interpreter being written, so it lands as
ordinary Scheme code in the port, not as new demands on the qfitzah substrate.
The substrate needs only four bounded extensions: file/argv/env syscall
primitives, 32-bit word arithmetic primitives, larger arenas, and a host-heap
reclamation mechanism (the one genuinely new design problem — rsc has no GC and
an interpreter loop conses host pairs on every call). The first demonstrable
milestone is qmes running `scaffold/boot/00-zero.scm` … `14-exit.scm` under
`MES_BOOT` with exit statuses identical to a reference `mes-m2` built via
nixpkgs' `m2-planet` + `mescc-tools`. The fixpoint experiment compares, file by
file, the `.s` (M1 assembly) output of `mescc -S` compiling `src/*.c` under
qmes vs. under mes-m2, then the hex2-linked binaries, then the classic
self-recompilation. Full fixpoint is plausible but compute- and debug-bound;
the committed-to deliverable is the boot ladder + a byte-identical
`mescc -S scaffold/hello.c`, with the full `src/*.c` sweep as the stretch goal.

## 1. Ground truth

### 1.1 What the qfitzah ladder provides (read: ARCHITECTURE.md, bootstrap/, tools/)

- Stage 0 seed `qfitzah.s` (~1.7 KiB i386 ELF): S-expr rewriter with
  structure-sharing, head-atom rule indexing, and normal-form memoization
  (ARCHITECTURE.md:23-49). Built by `nix build` (flake.nix:27-35: `as --32`,
  `ld -m elf_i386`, `objcopy`). Assembly of large programs is now ~linear
  (memoized ev; a full rsc self-compile is seconds, full suite ~31 s).
- Stage 1 `bootstrap/qfasm.qf1` (1441 lines, generated by
  tools/generate_qfasm.py): general symbolic i386 assembler; labels are
  arbitrary terms; emits complete ELFs.
- Stage 2 `bootstrap/scheme0.qfasm` → native minimal Scheme interpreter.
- Stage 3 `bootstrap/sc1.scm` + `sc1-reader.scm` + `sc1-runtime.qf1`:
  Scheme→qfasm compiler, self-hosts byte-identically.
- Stage 4 `bootstrap/rsc.scm` (902 lines) + `rsc-prelude.scm` +
  `rsc-runtime.qf1` (generated by tools/generate_rsc_runtime.py): R5RS-subset
  compiler, self-hosts byte-identically (tests/run.sh:307-331).

**The rsc dialect qmes must be written in** (this is the real interface):

- Values: 30-bit fixnums (tag `n*4+1`, rsc.scm:149,263), immediates nil/`#t`/
  `#f`/eof/unspecified (0x03/0x13/0x23/0x33/0x43), chars `c<<8|0x53`, pairs,
  and object cells with subtypes symbol/string/closure/prim/vector
  (generate_rsc_runtime.py:41-46, MEMORY: value tags).
- Memory: **bump arenas, no GC** — 192 MiB cell arena + 32 MiB byte arena +
  16 MiB read buffer, set in `HeapInit` (generate_rsc_runtime.py:116-130).
  Every host call conses: `compile-app` builds an arg list (rsc.scm:401-431)
  and `emit-prologue`/`bind-newenv` conses an env frame per lambda entry
  (rsc.scm:441-465). Nothing is ever freed.
- Language: `lambda` (incl. rest args), `define`, `set!`, `if`, `quote`,
  `begin`, `let`/`let*`/`letrec`/named-let/`case`/`do`/`when`/`unless`,
  `cond` (incl. `=>`), `and`/`or`, `quasiquote`, hygienic-ish `syntax-rules`
  (rsc.scm:506-843). Proper tail calls (tail applications JMP, rsc.scm:415-417).
- Primitives (generate_rsc_runtime.py:49-75): pairs, fixnum `+ - * quotient
  remainder = < > <= >=`, `display write newline`, `read-char peek-char`
  (**stdin/stdout only — no file I/O, no argv, no getenv**), chars,
  strings (mutable: `make-string`/`string-set!`), symbols, vectors, `apply`,
  `error`, `exit`. Plus the prelude library (rsc-prelude.scm).
- Out of scope today (ARCHITECTURE.md:152-157): bignums/floats, `call/cc`,
  `dynamic-wind`, `eval`, `delay/force`, `#(...)` read syntax.
- Source reader for the bootstrap is `sc1-reader.scm`: fixnums (decimal only),
  symbols, strings (`\n`/`\t` escapes only), `#t #f`, `#\<char>` with names
  space/newline/tab only, quote/quasiquote sugar, line comments
  (sc1-reader.scm:64-137). **No `#x`, no `#(`, no block comments** — qmes's
  *source* must stay inside this; qmes's *implemented* reader is unrestricted.
- Verification: `tests/run.sh result/bin/qfitzah` is the single gate; every
  stage and both fixpoints are byte-checked (tests/run.sh:271-362).

### 1.2 What Mes is and how it is built (read: third_party/mes @ f244b14, v0.27.1)

- Reference build (kaem.run:22-24 sets `cc_cpu=i386 mes_cpu=x86 stage0_cpu=x86`;
  kaem.run:30-165): **M2-Planet** compiles `include/mes/config.h`, ~80 `lib/`
  files, and `src/{builtins,core,display,eval-apply,gc,hash,lib,m2,math,mes,
  module,posix,reader,stack,string,struct,symbol,variable,vector}.c` to
  `m2/mes.M1`; **blood-elf** adds debug stubs; **M1** assembles to hex2;
  **hex2** links at base 0x1000000 → `bin/mes-m2`. All four tools are in
  nixpkgs (`m2-planet` 1.13.1, `mescc-tools` 1.7.0 incl. kaem) — the reference
  is buildable in this repo without Guix.
- Interpreter core: 6835 lines of C total (src/, `wc -l`). `struct scm` is
  three `long` words — type + two unions (include/mes/mes.h:28-56). **`long`
  = 32-bit on the i386 target.** 18 cell types (include/mes/constants.h:24-44):
  TCHAR TBYTES TCLOSURE TCONTINUATION TKEYWORD TMACRO TNUMBER TPAIR TPORT TREF
  TSPECIAL TSTRING TSTRUCT TSYMBOL TVALUES TBINDING TVECTOR TBROKEN_HEART.
  Numbers are plain signed longs, **no bignums, silent wraparound**.
- `mes_builtins()` (src/builtins.c:116-332) registers ~174 primitives across
  the src/*.c files (full census in the gap table below).
- Evaluator (src/eval-apply.c, 1072 lines): an explicit-stack trampoline VM —
  registers R0–R3 plus a `g_stack` array; ~25 `cell_vm_*` states; special
  forms quote/lambda/if/set!/begin/define/define-macro handled natively;
  `core:eval` / `core:eval-expanded` are TSPECIAL symbols (src/symbol.c:62-68);
  proper tail calls fall out of the state machine; **call/cc = snapshot of the
  explicit stack into a vector** (eval-apply.c:996-1010) — no C-stack tricks.
  Macros are TMACRO cells expanded at eval time from a `g_macros` hash.
- GC (src/gc.c, 865 lines): two-space Cheney stop-and-copy over a single
  malloc'd arena; `ARENA_SIZE` default 20 000 000 cells, overridable via
  `MES_ARENA`/`MES_MAX_ARENA`/`MES_STACK` (gc.c:54-73; bootstrap.sh.in:28-33
  exports MES_ARENA=20000000, MES_STACK=5000000); arena doubling on pressure;
  roots = symbols, `g_macros`, `g_ports`, modules, R0–R3, the VM stack, saved
  by `gc_push_frame` (5-cell frames).
- Boot: `main` opens `$MES_BOOT` (default `boot-5.scm`) under
  `$MES_PREFIX/mes/module/mes/` (src/mes.c:126-174), reads the whole file and
  evaluates it. boot-5.scm (227 lines) builds up from raw builtins:
  display/write wrappers, `and`/`or` as define-macros, `load`/`include`,
  `mes-use-module` (textual include + registry, mes/module/mes/module.mes:25-64),
  then modules base, quasiquote, let, scm (call/cc wrappers + dynamic-wind,
  scm.mes:286-321), srfi-13, fluids, catch (exceptions via call/cc + fluids,
  catch.mes:36-64), posix, guile, srfi-9 (records over TSTRUCT), syntax
  (syntax-rules via define-macro), guile-module (real module structs over
  hash tables), srfi-39, then `(mes main)` → `(top-main)`.
- The graduated capability ladder is `scaffold/boot/*.scm` (90 files,
  00-zero … 60-let-syntax plus call-cc.scm/gc.scm/memory.scm), run as
  `MES_BOOT=<test> mes` for 0x–4x, `MES_BOOT=boot-00.scm` + stdin for 5x,
  `MES_BOOT=boot-01.scm` for 6x (build-aux/test-boot.sh:30-38); pass = exit 0.
- MesCC (module/mescc.scm 416 + module/mescc/{compile 2828, M1 336, as 79,
  info 305, preprocess 159}.scm + one arch backend, i386/as.scm 655): C is
  parsed by **nyacc** (`(nyacc lang c99 parser)`, preprocess.scm:28 — nyacc is
  NOT in this tree; `mes/module/nyacc/` holds only 53 lines of stubs; INSTALL:31
  says nyacc 1.00.2+; **nixpkgs has no nyacc attr — it must be vendored**),
  compiled to immutable info records (info.scm:122-260, srfi-9 GNU
  `define-immutable-record-type` + functional `clone`), emitted as M1 text.
  `-S` stops there and is **pure Scheme + file I/O**; `-c`/link shells out to
  M1/hex2/blood-elf via `system*` (mescc.scm:202,234,252,309-310).
  MesCC output is deterministic: alists everywhere, no hash-table iteration,
  no timestamps; the only stamps are `%version` (= `getenv "%version"`,
  mescc.scm:44) and `MES_VERSION` from config.h (configure.sh:263).
  MesCC needs: srfi-1, srfi-9(-gnu), srfi-26 `cut`, `pmatch`, ice-9 optargs
  (`define*`/`#:key`), getopt-long, string ops incl. `string-split`/`-join`/
  `-drop`/`-index`, `ash`/`logxor`/`number->string` radix 16, string ports /
  `with-output-to-string` (Scheme-level: simple-format.mes:26-39) — **all of
  which exist as Mes Scheme modules already**; it does *not* use call/cc,
  dynamic-wind, floats, bignums, or hash tables directly (the module system
  underneath uses hash tables and catch uses call/cc, so the core must still
  provide them).

### 2.1 The host-heap problem (gap #6) — design sketch

qmes's persistent state must mirror mes.c's: *everything* (cells, strings,
stack, registers) lives in qmes-owned arrays allocated once at startup. Then
every host allocation after startup — arg-list pairs and env frames from rsc's
calling convention — is dead once control returns to the VM trampoline. Two
candidate mechanisms:

- **(a) Safepoint arena reset (recommended).** Two new runtime primitives:
  `(host-heap-mark)` → captures `GCellFree`, and `(host-heap-reset! m)` →
  restores it. The qmes main loop is a top-level trampoline: run N VM steps
  (each step a tail-call loop that returns to the trampoline), then reset the
  cell arena to the post-startup mark. Sound iff (i) all persistent qmes state
  is in the byte-arena vectors or in global cells whose values were allocated
  before the mark, and (ii) at the reset point the machine stack holds no
  pointers into the region being freed (true at the trampoline: compiled rsc
  code returns there with only immediates/global-reachable values live).
  Byte arena (vectors/strings) is *not* reset. Cost: ~20 lines of runtime, a
  coding discipline, and an assertion mode that poisons freed cells.
- **(b) Conservative host GC (fallback).** Mark-sweep free-list collector over
  the host cell arena, scanning machine stack + globals + EBP chain as
  ambiguous roots; non-moving so no stack maps needed. ~400 lines of generated
  qfasm. Strictly more general, meaningfully harder to get right.

Decision gate: milestone P1 ends with a stress test — a tail loop that conses
per iteration through a trampoline for 10⁹ iterations in constant memory. If
the discipline in (a) proves too error-prone during the P2/P3 port, fall back
to (b) before P4.

## 3. Strategy (Q2)

### Strategy A — port `src/*.c` to the rsc dialect; run Mes's Scheme unmodified. **Recommended.**

Write `bootstrap/qmes.scm` (plus split files) as a *transliteration* of the C
core: same 18 cell types (type/car/cdr in three parallel or one interleaved
vector-backed arena), same ~174 builtins with the same names (the `core:*`
namespace included), same `cell_vm_*` state machine, same reader, same Cheney
GC, same MES_BOOT/MES_PREFIX behavior (mes.c:126-174). Compile it with rsc →
`qmes.elf`, a native i386 binary. Then `MES_BOOT=boot-5.scm MES_PREFIX=third_party/mes
qmes` *is* Mes, and MesCC runs on it unmodified.

Why this wins:
- Fidelity is checkable at every step: mes-m2 is the executable spec, the
  scaffold/boot ladder is the pre-built test sequence, and divergences bisect
  against a working reference.
- Everything hard (call/cc, GC, macros, modules) is interior to the port —
  the substrate additions (gaps 2,3,6,11) are small and independently testable.
- It satisfies the thesis exactly: seed → rewrite rules → Scheme compiler →
  Scheme interpreter → Mes boot → MesCC. No C compiler below Mes.
- The explicit-stack VM design of eval-apply.c is *made* for this: proper tail
  calls, continuations, and GC roots all live in one array qmes owns.

### Strategy B — build a C-subset→qfasm compiler in rsc and compile `src/*.c`. **Rejected.**

Honestly assessed: it "works" but does not satisfy the thesis — it re-creates
the M2-Planet role, so the bootstrap once again passes through a C semantic
layer; the effort is MesCC-scale (a C99-subset front end ≈ nyacc + compile.scm
≈ 7–13k lines) *plus* a new backend; and the resulting binary would differ
bytewise from mes-m2 anyway (different codegen), so the equivalence argument
still reduces to comparing MesCC outputs — which Strategy A reaches without
writing a C compiler. The only scenario to revisit B is if interpreted-qmes
performance proves fatally slow for the full fixpoint (§8), and even then the
partial demonstration under A remains the better result.

## 4. First demonstrable milestone and the ladder after it (Q3)

**M-first:** `qmes.elf` (compiled by rsc, assembled by the seed) runs
`MES_BOOT=scaffold/boot/00-zero.scm` … `14-exit.scm` and each exits with the
same status as reference `mes-m2` (14-exit tests `exit` with a status; earlier
rungs are literals/quote/if). Concretely testable:

```sh
for t in 00-zero 01-true 02-symbol 03-string 04-quote 05-list 06-tick 07-if 08-if-if \
         10-cons 11-list 12-car 13-cdr 14-exit; do
  MES_BOOT=$PWD/third_party/mes/scaffold/boot/$t.scm ./qmes.elf; a=$?
  MES_BOOT=$PWD/third_party/mes/scaffold/boot/$t.scm ./mes-m2;   b=$?
  [ "$a" = "$b" ] || echo "DIVERGE $t: $a vs $b"
done
```

This proves: rsc can compile a real interpreter; the cell model, reader
subset, symbol table, eval core, and exit path all work; and the differential
harness against mes-m2 exists. It requires gaps 2 (numbers), 3 (open/getenv for
MES_BOOT), and the P2 port skeleton — but *not* GC, macros, ports, call/cc.

The sequence after it follows the scaffold numbering exactly (test-boot.sh
rules: plain `MES_BOOT=<test>` for 0x–4x, `MES_BOOT=boot-00.scm` piping the
test for 5x, `boot-01.scm` for 6x):

1. 15-display … 17-* → display.c port, `equal2?`, string builtins, keywords,
   `open-input-string`.
2. 2x–3x → define/lambda/closures/set!, begin semantics, capture tests.
3. 38-simple-format → `with-output-to-string` path (write-byte redirection).
4. 40–4f → **define-macro machinery** (TMACRO, begin_expand states), when/or,
   quasiquote-at-eval, let.
5. 50–53 → keywords, primitive-load, **module.mes loading**.
6. 60-let-syntax → syntax.mes's define-macro-based syntax-rules.
7. call-cc.scm, gc.scm, memory.scm → continuations + the GC port.
8. `MES_BOOT=boot-5.scm` reaching `(top-main)` → full boot: modules, catch,
   fluids, srfi-9, guile-module. Checkpoint: the REPL banner / `mes --help`.
9. MesCC smoke: `mescc -S scaffold/hello.c` byte-equal to reference.

## 5. The fixpoint-equivalence experiment (Q4)

**Operational definition.** Fix the tree at f244b14 (v0.27.1). Let
`SRC` = the `mes_SOURCES` set kaem.run compiles (the 19 `src/*.c` files +
`lib/` support units, kaem.run:30-144). Define three checks, strongest last:

- **F1 — path-independent compiler output (the core claim).** For every
  `f ∈ SRC ∪ {scaffold/hello.c}`, run MesCC in compile-only mode under both
  hosts and byte-compare:

  ```sh
  env - PATH=… LANG= MES_DEBUG=0 %version=0.27.1 \
      MES_ARENA=20000000 MES_MAX_ARENA=20000000 MES_STACK=5000000 \
      MES_PREFIX=$PWD/third_party/mes srcdest=$PWD/third_party/mes/ \
    $HOST third_party/mes/scripts/mescc.scm -- \
      -S -m 32 --arch=x86 -D HAVE_CONFIG_H=1 \
      -I third_party/mes/include -I build/include \
      -o out.$HOST/$f.s third_party/mes/$f
  cmp out.mes-m2/$f.s out.qmes/$f.s
  ```

  (`-S` output is pure Scheme + file I/O — no `system*` needed; mescc.scm
  shells out only for `-c`/link, mescc.scm:202-252.)
- **F2 — identical binary.** Assemble/link both `.s` sets with the *same*
  mescc-tools (`M1`, `blood-elf`, `hex2` — shared by both paths, so they add
  no trust): produce `bin/mes-mescc.ref` and `bin/mes-mescc.qmes`;
  `cmp` them. This mirrors what bootstrap.sh.in does with `$CC = mescc`
  (bootstrap.sh.in:122-134) minus the libc archive steps, which the harness
  scripts replicate.
- **F3 — classic self-recompilation fixpoint.** Run the F1 sweep a third time
  with `HOST = bin/mes-mescc.qmes` (the Mes binary MesCC itself produced on
  the qfitzah path). Its `.s` output must equal F1's. At that point the
  artifact is a fixpoint of "MesCC compiling src/*.c" reached with no C
  compiler in qfitzah's ancestry.

**Reference side.** Build once via nix: `nix shell nixpkgs#m2-planet
nixpkgs#mescc-tools` then run the kaem.run sequence (kaem is part of
mescc-tools) from a `tools/build-mes-reference.sh` that transcribes
kaem.x86 → `bin/mes-m2`. No prepackaged mes exists in nixpkgs; building from
the submodule is the plan of record. Record sha256 of `bin/mes-m2` and of
every reference `.s` in `tests/mes-reference.sha256` so later runs don't need
the M2-Planet toolchain at all.

**Determinism hazards** (each pinned by the harness): `%version` env
(mescc.scm:44) and `MES_VERSION` in config.h (configure.sh:263) must match;
`LANG=` cleared (bootstrap.sh.in:27); `MES_DEBUG` equal (debug prints go to
stderr but gate reads, boot-03.scm:126-135); identical `MES_PREFIX`/`srcdest`
and cwd (path strings can reach `.s` via `__FILE__`-style macros and error
text); identical include search order and `-D` set; identical `MES_BOOT`
(default boot-5.scm); nyacc version identical by construction (vendored).
`MES_ARENA` sizing must not affect output — verify once by running the
reference twice with different arenas. mescc processes alists in insertion
order and uses no hash iteration (module/mescc/info.scm records; M1.scm
linear passes), so no ordering hazard is expected beyond these.

## 6. Portability: build with and without nix (Q5)

Environment fact: this machine has git/make/m4/python3/nix but **no host
gcc/as/ld/guile**. nixpkgs (pinned nixos-unstable 64c08a7) provides
`m2-planet` 1.13.1 and `mescc-tools` 1.7.0; it does **not** provide nyacc or
mes.

Design:

- **Seed acquisition — three-way fallback**, in a top-level `Makefile`:
  1. `bootstrap/seed/qfitzah` — a committed prebuilt seed binary (~1.7 KiB),
     with `bootstrap/seed/SHA256SUMS`. This is philosophically clean: the seed
     *is* the trusted binary root of the whole project, it is hand-auditable,
     and `qfitzah.s` remains its source. Add `make verify-seed` = rebuild via
     nix (or as/ld) and `cmp` against the committed binary.
  2. If `as` and `ld` exist: build from `qfitzah.s` exactly as flake.nix:30-32
     does (`as --32`, `ld -m elf_i386 -static -z noseparate-code`, `objcopy -S
     -R .note.gnu.build-id -R .note.gnu.property`).
  3. Else if `nix` exists: `nix build .#qfitzah` → `result/bin/qfitzah`.
- **The qfitzah→qmes ladder needs only `sh`, `cat`, and the seed.** Every
  stage is `cat <rules> <source> | qfitzah > out` (tests/run.sh:137,186-190,
  247-251,282-284,312-325). python3 is used only to *regenerate committed
  sources* (qfasm.qf1, runtimes) and never at build time. So "build Mes
  without nix" holds on any x86-64/i386 Linux with 32-bit exec support
  (CONFIG_IA32_EMULATION), given the committed seed.
- **The reference/M2-Planet side is nix-gated here** (`make mes-reference`
  requires `nix` or host-installed `M2-Planet`+`mescc-tools`+`kaem`). That is
  acceptable: it produces the *comparison baseline*, not the artifact under
  test, and its outputs' hashes are committed so CI and offline machines can
  check F1/F2 against `tests/mes-reference.sha256` without rebuilding it.
- **nyacc**: vendor the nyacc 1.00.2 release tarball as `third_party/nyacc`
  (source-only Scheme; INSTALL:31 pins compatibility). No nix dependency.
- Makefile entry points: `make seed`, `make qmes` (ladder → qmes.elf),
  `make check` (tests/run.sh), `make boot-ladder` (scaffold differential),
  `make mes-reference` (nix-gated), `make fixpoint` (F1→F3).

## 8. Honest scope verdict (Q7)

**Achievable, with one caveat each on memory and time.** Nothing in Mes's core
is conceptually out of reach of the rsc dialect: the interpreter is an
explicit-stack state machine over a flat arena — exactly the shape a
GC-less, fixnum-only host can express — and call/cc, macros, modules and GC
are all interior to the port. The genuine risks, in order:

1. **Host-heap reclamation (gap 6).** The safepoint-reset design is simple but
   relies on a discipline the 6.8-kloc port must never violate; the fallback
   (conservative host GC) is a real sub-project. This is the only place the
   plan could grow a new mechanism.
2. **Throughput of the full sweep.** qmes (rsc codegen) should be within a
   small factor of mes-m2 (M2-Planet codegen) — both are naive compilers and
   the interpretation depth is identical — but MesCC+nyacc compiling all of
   `src/*.c` under any Mes takes real time; under a 2–5× slower host it could
   be hours per full F1 sweep, making divergence-hunting iterations expensive.
3. **Long-tail semantic divergences** (reader corner cases, `equal2?`,
   keyword/port edge behavior, macro-expansion order) surfacing only in F1 as
   byte diffs. Mitigated by the differential ladder from M-first onward — every
   rung compares against mes-m2, so divergence is caught at the smallest
   reproducer available.

**Committed deliverable** (high confidence): qmes built by the qfitzah ladder
passes the entire scaffold/boot ladder incl. gc/call-cc, boots unmodified
boot-5.scm to `top-main`, and `mescc -S scaffold/hello.c` under qmes is
byte-identical to the M2-Planet-path reference — already a complete
demonstration that assembly → pattern-matching → Scheme reaches a working Mes
with no C below it.

**Stretch deliverable** (plausible, compute/debug-bound, no known conceptual
blocker): the full F1/F2/F3 fixpoint — the MesCC-compiled `mes` binary,
byte-identical whether its host interpreter came from M2-Planet or from the
qfitzah ladder. If P6 stalls, the honest published claim is the committed
deliverable plus the F1 subset that does pass, with remaining diverging files
enumerated.
