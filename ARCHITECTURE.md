# Architecture

Qfitzah is a self-hosting Scheme compiler built as a ladder of small language
processors, rooted in a tiny hand-written term rewriter. Each rung is a real
processor that runs the rung above it; each is only as large as it needs to be
to make the next comfortable to write.

```text
Stage 0  qfitzah.s      seed: pattern-matching term rewriter (i386 ELF)
Stage 1  qfasm.qf1      general symbolic assembler (rewrite rules)
Stage 2  scheme0.qfasm  minimal Scheme interpreter (qfasm -> native ELF)
Stage 3  sc1.scm        Scheme-subset compiler, written in the scheme0 subset
Stage 4  rsc.scm        R5RS-subset-to-asm compiler, written in the sc1 subset
```

Every artifact is produced by running the stage below it — the seed assembles
the assembler's output, the assembler builds the interpreter, the interpreter
runs the compiler, the compiler compiles the next compiler. Host tools
(`python3`) only generate *source* (rule tables, fixtures); they never emit
object bytes. Two stages close the loop by rebuilding their own source to a
byte-identical fixpoint.

## Stage 0: Seed (`qfitzah.s`)

A ~1.7 KiB static i386 ELF implementing the rewrite language: an S-expression
reader, atom interning, newest-first rewrite rules, structural matching with
repeated-variable equality, substitution that preserves unmatched template
variables, `(Bytes ...)` byte output, and normal-form printing. This is the
trusted root, kept small and hand-auditable. It gains no evaluation semantics
as the ladder grows — arithmetic, assembly, and compilation all live above it.

Three properties keep it fast enough to host the stages above, all invisible to
the language semantics:

- **Structure sharing.** `evlis` returns the original pair when neither field
  changed after evaluation, so re-walking already-normal data allocates
  nothing.
- **Head-atom rule indexing.** Each interned atom carries a bucket of the rules
  whose pattern begins with it, so evaluating a term scans only plausible
  candidates. Rules whose pattern head is not a constant atom live on a generic
  list consulted after the bucket, and therefore rank below all head-indexed
  rules.
- **Normal-form memoization.** Pairs are immutable and never freed, so `ev(t)`
  is a pure function of the pointer `t` and the current rule set. A
  direct-mapped cache keyed on the pair pointer (invalidated by a generation
  counter bumped when a rule is added) normalizes each subterm once. This is
  what keeps the assembler's passes linear: threading a large instruction chain
  or symbol table through a recursive rewrite revisits those shared subterms
  once per step, which without the cache is quadratic.

## Stage 1: Assembler (`bootstrap/qfasm.qf1`)

A symbolic i386 assembler expressed entirely in rewrite rules, generated by
`bootstrap/gen-qfasm.scm` from a single instruction spec so instruction sizes
and byte emissions cannot disagree. It handles symbolic labels, structured
32-bit arithmetic, and complete ELF emission over programs of any size.

Numbers are little-endian nybble lists, `(N d0 ... d7)`; add, negate, and
subtract chain through generated single-nybble fact tables, and byte atoms come
from a generated `(HB hi lo)` table because the seed cannot synthesize atoms at
runtime. Label arithmetic, range-checked rel8, rel32 branches and calls, ELF
header fields, and alignment all compute from these — there are no fixed-size
lookup tables to outgrow.

Programs are data: `(Assemble (Program entry bss code))`, where `code` is a
right-nested `(Ins instr (Ins ... End))` chain. Label names are arbitrary
terms compared structurally by the symbol table, so scoped labels (e.g.
`(Local Reader 1)`) are free. Two passes assign label addresses then emit
bytes with resolved operands. The instruction set grows by adding rules, never
by adding number facts.

## Stage 2: Interpreter (`bootstrap/scheme0.qfasm`)

A minimal Scheme interpreter written in Stage 1 assembly, generated by
`bootstrap/gen-scheme0.scm` and assembled by the seed into a native ELF. It is the
first rung to leave the rewrite substrate for a real functional language with
unbounded data and arithmetic.

- **Reader:** fixnums, symbols, pairs and dotted pairs, `'` quote, strings,
  characters, booleans, comments.
- **Evaluator:** `lambda` with proper closures and rest parameters, `define`,
  `set!`, `if`, `quote`, `begin`, `let`, `cond`, `and`, `or`; tail calls run
  in constant stack.
- **Values:** tagged 32-bit words — pairs, fixnums, object cells (symbol /
  string / closure / primitive), and immediates (nil, booleans, characters,
  eof, unspecified).
- **Primitives:** pairs, fixnum arithmetic and comparison, character/string/
  symbol operations, and stdin/stdout, each a first-class global closure.
- **Memory:** a bump allocator over a large arena, sufficient for a
  short-lived interpreter run — the same argument the seed makes.

## Stage 3: Compiler (`bootstrap/sc1.scm`)

A Scheme-to-qfasm compiler written strictly in the scheme0 subset, so scheme0
runs it interpreted and it compiles its own source. It compiles the sc1 subset
(the scheme0 surface plus first-class primitives) to qfasm, which the seed then
assembles to a native ELF — the first *compiled*, natively fast Scheme in the
ladder.

The reader is `bootstrap/sc1-reader.scm`; the fixed assembly runtime (heap
init, `cons`, object allocation, buffered I/O, the printer, symbol interning,
and every primitive) is `bootstrap/sc1-runtime.qf1`, generated by
`bootstrap/gen-sc1-runtime.scm` and expanded by the seed through
`(RuntimeCode ...)` / `(RuntimeData ...)` macros.

Compilation model: closures are subtype-2 objects with a `(code . env)`
payload; the environment is a heap frame-chain held in `EBP`; variables compile
to lexical `(depth, index)` walks or global static cells; quoted structures
become static data, with a startup pass interning quoted symbols so
`string->symbol` round-trips; codegen is direct-style with proper tail calls
(tail applications JMP, non-tail CALL), so tail recursion runs in constant
machine stack.

The stage closes with a fixpoint: the native `sc1.elf` recompiling its own
source (`sc1-reader.scm` + `sc1.scm`) produces output byte-identical to the
interpreted compile.

## Stage 4: R5RS Compiler (`bootstrap/rsc.scm`)

An R5RS-subset compiler, written strictly in the sc1 subset so sc1 compiles it,
that adds the R5RS surface language on top of sc1 and self-hosts to a
byte-identical fixpoint. It is sc1's codegen preceded by a macro-expansion pass
and backed by a wider runtime (`bootstrap/rsc-runtime.qf1`, generated by
`bootstrap/gen-rsc-runtime.scm`). Derived special forms lower to the sc1 core;
library procedures that need the machine are runtime primitives; the rest of
the library is a fixed Scheme prelude (`bootstrap/rsc-prelude.scm`) the compiler
prepends to every program. `rsc.scm` itself stays in the sc1 subset and uses
none of the prelude, so its fixpoint re-exercises sc1's codegen while the new
surface is covered by a dedicated corpus.

What it adds over sc1:

- **Hygienic `syntax-rules` macros** — `define-syntax`, `let-syntax`,
  `letrec-syntax`, with literals, ellipsis, and nested patterns. Every form is
  expanded to the sc1 core before codegen. Template identifiers that are not
  pattern variables, literals, or known names are gensym-renamed per expansion,
  so a macro's introduced temporaries cannot capture a caller's bindings.
- **`quasiquote`** / `unquote` / `unquote-splicing`, nested with correct depth.
- **Derived forms** — `let*`, `letrec`, `letrec*`, named `let`, `case`, `when`,
  `unless`, `do`, and `cond` with `=>`.
- **Vectors** — a new object subtype with `make-vector`, `vector`,
  `vector-ref`, `vector-set!`, `vector-length`, `vector?`, `vector->list`,
  `list->vector`, `vector-fill!`, printed as `#(...)`.
- **`apply` and varargs**, tail-proper.
- **Standard library** — `equal?`, the `assoc`/`member` family, list
  operations, integer helpers, `number->string`, and the character and string
  libraries.

Bootstrap and fixpoint: sc1 compiles `rsc.scm` to `rscA`; `rscA` compiles
`rsc.scm` to `rscB`; `rscB` compiles `rsc.scm` to `rscC`; `rscB` and `rscC` are
byte-identical.

The implemented language is fixnum-based and minimal but correct — what is
present follows R5RS semantics. Out of scope: bignums and the wider numeric
tower, floats and rationals, `call/cc` and `dynamic-wind`, first-class `eval`,
`delay`/`force`, and `#(...)` vector read syntax (vectors are built with the
constructors above).

## Verification

`tests/run.sh` is the single entry point (`nix flake check` runs it). It
exercises the seed's rewrite semantics, then assembles and runs each stage:
the Stage 1 assembler against an independent byte-level model (including an
8 KiB, 2868-instruction program), the scheme0 interpreter and sc1 compiler over
their corpora, the R5RS corpus through rsc, and both self-host fixpoints. Every
boundary that has a byte-identical check is checked: the assembler's
differential fixtures, sc1's self-compilation, and rsc's fixpoint.
