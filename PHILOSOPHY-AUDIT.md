# Philosophy audit

## Verdict

The ladder is real, but the strongest claims were not justified. It is a
**source bootstrap rooted in a host-assembled seed**, not yet a bootstrap whose
entire authoring and verification story closes over that seed. Self-compilation
is valuable evidence of consistency, not proof of correctness or provenance.
There is no evidence here of intentional deception; “cheating” below means an
unacknowledged dependency or a test that establishes less than its description.

This audit distinguishes three things:

1. **Executable ancestry:** what programs actually produce executable bytes?
2. **Source ancestry:** what computes the implementation sources we check in?
3. **Semantic evidence:** what do the tests actually establish?

No Python is needed to run the existing build/test path, and no Python was run
for this audit. That does not erase the Python ancestry of checked-in sources.

## Trust boundary and baseline findings

| Boundary | Actual dependency / limitation |
| --- | --- |
| Host to Stage 0 | `flake.nix` runs GNU `as`, `ld`, and `objcopy`. Nix/nixpkgs, the shell, binutils, Linux/i386 execution and the hardware are outside the seed. |
| Stage 0 to Stage 1 | The seed interprets `bootstrap/qfasm.qf1`; there is no separate assembler executable. Its original arithmetic/encoding tables and instruction rules were computed by `tools/generate_qfasm.py`. |
| Stage 1 to Stage 2 | qfasm emits the scheme0 ELF from symbolic assembly. `tools/build_scheme0.py` constructs that assembly, including repeated initialization and data. Calling it only a formatter understates source-generation work. |
| Stages 3 and 4 | Scheme compilers emit assembly, not complete stand-alone binaries. Both depend on fixed runtime rule sources generated by Python; the seed plus qfasm assemble every generation. |
| Test oracles | Checked-in hex/arithmetic fixtures come from a Python model. They are expected data, not executable bootstrap inputs. They are useful but not a proof independent of all shared design mistakes. |
| sc1 fixpoint | Originally compared interpreted/native **qfasm text**, not two assembled ELFs. |
| rsc fixpoint | Originally compared B/C **qfasm text**, never assembled C, and ran the feature corpus only through A. |
| Resource limits | Static input/output buffers, atom table and bump arenas are finite and mostly unchecked. “Unbounded data”, “any program size”, and unconditional linearity are too strong. |
| Language semantics | The seed's indexed rules outrank generic rules irrespective of age. This is not global newest-first semantics. rsc's gensym-based macro expansion is not a complete lexical-scope hygiene implementation. |

There are no checked-in `.elf` or `.bin` stage executables. Generated executables
are the intended *outputs* of a native compiler ladder; eliminating all binaries
would mean interpreting everything instead. The useful constraint is **no opaque
prebuilt executable as a later-stage input**. Merely spelling a binary as a giant
hex list, or renaming generated code “source”, does not satisfy that constraint.

## Policy: what should count as a faithful bootstrap?

- Every production executable must be built from reviewed source by the declared
  predecessor(s). List the runtime and assembler inputs as well as the compiler.
- No saved stage executable, host Scheme, Python, or alternate host compiler may
  silently substitute for a failing stage. Tests must fail closed.
- Source generators are implementation dependencies, not exempt because they
  output text. Either maintain their readable output as genuine source with
  provenance retained, or port the generator to an earlier rung and reproduce
  its output. Do not hide a dependency by deleting its name from documentation.
- Native opcode constants, ABI tags and ELF constants are legitimate assembly
  source; wholesale opaque executable blobs are not. Keep labels/relocations
  symbolic and data distinguishable from code.
- Exact-output tests, full executable comparisons and post-fixpoint execution
  complement one another. No fixed point proves general language correctness,
  full hygiene, resistance to a trusting-trust attack, or a minimal trusted root.
- Shell utilities may orchestrate, compare and provide independent test oracles.
  They must not implement a production compiler pass or manufacture its code.

## Extending the seed without moving the compiler into it

The best first extension is a missing **representation operation**, not a large
arithmetic runtime: let byte output consume `(Hex high low)` with two computed
hex-digit terms. The old emitter required an interned two-character atom, forcing
Stage 1 to enumerate all 256 combinations. A structured byte eliminates that
particular table without atom concatenation, mutation, or new evaluation rules.
Arithmetic, relocation and instruction selection should remain rewrite programs.

The byte boundary must validate its input. In the original emitter, an unresolved
relocation, out-of-range rel8, or unknown instruction could reach `emit_byte` as a
pair and be interpreted as an atom pointer. A stuck rewrite is not a diagnostic.
Reject invalid byte trees with a nonzero exit status; never flush a partially
encoded failing record. A caller must still discard the output of a failed run:
previous successful records cannot be retracted.

Further useful work, in dependency order:

1. Replace generated addition/ModRM tables with small bit/digit algorithms in
   Qfitzah. Exhaustively test the finite input domain and retain independent
   whole-program byte checks. Measure heap/time: a smaller source that makes
   scheme0 assembly exhaust the arena is not a usable bootstrap.
2. Express instruction descriptions once in Qfitzah, deriving both size and
   emission there. A generic two-pass traversal should consume those descriptions;
   duplicating sizes manually is not an improvement over the existing generator.
3. Add a Qfitzah-level flat instruction-list/block notation so humans can maintain
   scheme0/runtime assembly without Python's chunking and parenthesis formatting.
   Preserve comments, named ABI constants and primitive declarations. Prove each
   migration byte-identical to the old artifact before dropping the old generator.
4. Port repetitive runtime/primitive-table generation to that notation or to
   scheme0 Scheme. For the latter, build scheme0 first; a generator needed to
   build scheme0 cannot itself require scheme0. Explicitly inventory this cycle.
5. If general atom/text construction remains necessary, design a pure byte-list
   to atom operation with a defined empty/invalid-input policy and bounds checks.
   Do not casually add `eval`, file loading, syscalls or machine integers just to
   make the seed look small while moving host functionality behind primitives.
6. Close the root separately: express the seed in qfasm, bootstrap it from the
   current seed, compare and audit the result. This still needs an explicitly
   trusted initial seed (or an independently verified hex/bootstrap path); a
   self-rebuild does not make GNU binutils disappear from historical ancestry.

## Remaining obligations

This is not a claim that all cheating has been eliminated. The Python-generated
scheme0 and runtime sources, incomplete Scheme semantics, unchecked resource
limits, and host-assembled root remain work. A complete removal requires the
source migrations above, not merely another successful self-host fixpoint.
